# Flexible California street-address lookup

The existing free Census `geographies/onelineaddress` source remains the only geocoder. No AI, credentials, fallback provider or URL fetching was added. The [official Census API documentation](https://geocoding.geo.census.gov/geocoder/Geocoding_Services_API.html), inspected 2026-11-07 (page updated February 2026), describes a numbered structure address and a point calculated along an address range. This is neither rooftop precision nor proof of delivery, a unit location or entrance. The documented split-address equivalent needs street + ZIP, or street + city + state. A city/ZIP centroid is never substituted.

## Input and resolution policy

- The API accepts up to 1,000 raw characters. Missing/invalid JSON, empty input, obvious non-address input, PO boxes and links receive actionable 400 errors. The form no longer blocks short input with a formatting-based `minLength` rule. Multiline paste preserves separators before a text input can delete its line breaks.
- Unicode compatibility normalization handles full-width digits; Unicode whitespace, line breaks, semicolons, repeated commas, curly apostrophes and dash variants are normalized. Casing and ordinary street punctuation remain freeform. A trailing US/USA/United States suffix and an initial `Address:`/`Location:` label are omitted. Recognized state names/California abbreviations become postal codes in locality positions; street names such as California Street remain intact.
- When no explicit state is recognized, California is the search context unless a supplied ZIP is outside the California prefix range. No city, ZIP or coordinate is invented. The assumption is disclosed in the help, interpretation metadata and candidate precision text. Explicit non-CA state/ZIP constraints are retained; non-CA source matches keep the existing candidate error behavior.
- Try the normalized input first. Only a successful, empty Census response permits a further interpretation: numbered street before supplied city/state/ZIP components; then omission of recognizable unit/floor markers, comma-separated public-building context (e.g. Library/City Hall), and ZIP+4 extension. The house number, street and locality remain. This is a conservative deterministic helper, not a universal postal parser. Unknown prose and unclear component order may still need editing.
- At most **three distinct source requests**, sequentially, share **one 20-second deadline** and the caller's cancellation signal. Outages, HTTP failures, malformed responses and cancellations do not trigger alternate queries. Stop at the first nonempty response and preserve every candidate, including ambiguous or unusable ones; do not select the first candidate automatically or broaden after an unusable match.
- Require street-range components, a TIGER line ID, finite coordinates and a California Census2020 tract. Pass the unmodified matched label/point/2020 tract into the existing `selection()` cross-check against full CES lookup geometry. Tract-boundary, coverage and mismatch errors remain errors. Display geometry never assigns membership. Every valid candidate still requires explicit confirmation.

## Additive response fields and privacy

Existing shapes remain supported: 200 `{ candidates }`, 400/404/503 `{ error }`; candidate-level errors remain in 200 arrays. Success and no-match responses additionally carry `interpretation`: `normalizedAddress`, `queryAddress` (the last/accepted interpretation), `assumedCalifornia`, `adjustments` (readable omissions/reordering), and `requests`. Valid candidates also carry `inputInterpretation` with the same metadata and append applicable interpretation notes to their existing `precision` text. No source confidence percentage is invented. These are request-local response fields, not persisted search history.

Upstream fetches and all API responses use `no-store`. No user search logs, files, storage or query caches were added. Only the fixed HTTPS Census endpoint is fetched, with redirects refused; a pasted URL is rejected rather than opened. Existing cached civic examples remain separate and unchanged.

## Worker evidence and original integration gate

Pure tests cover Oakland/Fresno input variants (case, full states/abbreviations, Unicode, pasted lines, missing state, reordered components, unit/public-building context and ZIP+4), preservation of explicit non-CA input, ambiguity, transport budget/deadline/cancellation, malformed sources and missing street-range precision. These are normalization and mocked transport checks, **not live resolution evidence**.

Live requests in this restricted worker could not be verified: shell DNS failed; the web tool returned “not accessible” for Oakland/Fresno baseline, missing-state and country-name queries. Official documentation was accessible. Attempt details and the bounded public-address probe remain in the worker tree and were separately preserved in main at `artifacts/refinement/address-worker/`; ignored files do not merge.

The original integration gate required the focused tests/typecheck, a combined build, sequential rendered tests and source-backed live civic queries. Integration results below complete those checks. The mocked UI cases cover multiline paste, ambiguous candidate confirmation and stale-request cancellation; the API case rejects invalid inputs without a provider request. No server, browser, performance test or own-worktree build was run by the worker itself. Mobile remains deferred.

Provider gaps remain explicit: arbitrary prose, misspellings, incomplete/ambiguous locality, unsupported units, renamed/new/unrecognized streets and non-structure addresses may not resolve. Revisit additional normalization only with retained public-address evidence; another provider needs an integration-owner checkpoint. No facility access, personal health, data version or building rendering contract changes are included.

## Combined local verification — 2026-11-08

The integration process had working live Census access. A fresh production build, with no `ATLAS_BACKEND_ORIGIN`, passed twelve sequential actual `/api/geocode` cases: ten valid Oakland/Fresno variants (baseline, lowercase, full-width digits/Unicode spacing, pasted lines, state/country names, omitted state, city-first, ZIP-first, unit/ZIP+4 and building-name context), one explicit outside-California address and one nonexistent numbered street. Every valid variant retained its baseline source coordinate and exact CES/Census2020 tract. The outside address returned its existing candidate error; the nonexistent street returned 404. All responses were `no-store`.

All three address UI/API regression cases passed in the final combined desktop run. All twelve live cases happened to complete on the first normalized source query. This demonstrates those source-backed inputs; fallback request ordering, ambiguity, deadline/cancellation and precision rejection remain covered by the thirteen focused transport/input tests. It does not establish universal parsing, typo repair or rooftop precision. Raw public civic evidence and summaries are retained in `artifacts/refinement/live-address/`; the worker's blocked attempts were copied to `artifacts/refinement/address-worker/`.
